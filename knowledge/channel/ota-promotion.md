## 0. 一句话

用户问「美团/携程这个促销要不要报」时，先问四件事，再给 **报 / 不报 / 只报肩日**：

1. **谁出资**（平台 / 酒店 / 共出）  
2. **净价**（Gross − 酒店承担折扣 − 佣金 − 加佣/投放）  
3. 适用 Stay Date 是否已经 **Pace Ahead** / Pickup Fast  
4. 会不会 **砸高峰**（日期盖 Peak、连住打穿地板、低价 Rate Plan 泄漏）

曝光不是决策。Gross 不是决策。销售口中的「不参加降权」默认 **Need Verification**。

## 1. Gross vs 谁出资 vs Net

```
客人看到的成交价     = Gross 或划线后实付（声明口径）
酒店承担的折扣       = 商户优惠（店出）
平台补贴             = 平台单独出资（店可能仍按原底价结）
共出                 = 各承担一段；比例未知则拆不开
Commission / 加佣    = 合同；本库不填假 %
Net                  = 酒店实收 − 已声明渠道成本
```

与 `net-contribution.md` 同一式。缺费率：**不算假精确净额**，只比结构（谁打穿地板、谁占高峰配额）。

| 出资 | 顾问含义 | 报名前必须问 |
| --- | --- | --- |
| **平台出** | 折扣可能不进店成本；仍可能有加佣/流量包 | 结算是否仍按原 BAR？有无加佣？ |
| **酒店出** | 折扣 = 降价。按围栏/降价尺审 | 折扣 %、盖哪些 Stay Date、能否按日关 |
| **共出** | 酒店段按店出审；平台段未知则保守 | 酒店承担上限；共出比例（常 NV） |
| **Unknown** | 默认按**店出**估最坏净价 | 用户合同 / 后台活动页 |

**携程 C 端《酒店算法公示》（S，2026-08-20 打开，不是活动目录）：**

- 房价由商户自主定。实付 = 基础房价 − 优惠。  
- **商户优惠（店报名并承担成本）** 公示举例：贵宾价、一起订专享、连住优惠、早鸟优惠、限时抢购、门店首单、今夜甩卖、多间优惠、学生专享、超值返现、满减券/折扣券。页写「以页面实际展示为准」。  
- **平台单独或共出：** 「特惠券」写携程单独出资；「十亿豪补」写单独或与商户共同出资。  

这些是 **C 端标签分类**，**不是** 2026 商家大促日历。禁止把标签名单写成「今年必须报的活动」。

## 3. 三结果：报 / 不报 / 只报肩日

### 3.1 报（须同时接近）

1. **谁出资已知**（公示分类或用户合同）。店出部分算得进 Net。  
2. **净价不打穿**：促销净 ≥ 该日 BAR 净，或店出折扣落在围栏 **−3–5%**（档 E），且不叠加再破地板。  
3. 适用日 **不是** 已证实 Peak / Sellout / Early Sellout / citywide。  
4. Pace **非 Ahead**，Pickup **非 Fast**（Ahead+Fast 走关低价，不报名）。  
5. 能按日关；高峰日该计划保持关。  
6. 市场不是「也弱还逼深折」——市场冰则 BAR 不动（do-not-cut）。

弱日、真增量、平台出资或浅围栏：可以报。配额建议 ≤ 该日剩余 20–30%（Hypothesis），避免卖穿。

### 3.2 不报（任一硬条件）

| # | 硬条件 | 改做 |
| --- | --- | --- |
| S1 | 适用日 Pace Ahead **或** Pickup Fast | 关低价；价按 how-much-to-move |
| S2 | 已证实 Peak / 事件核心夜 / 压缩日 | 高峰默认拒打穿地板的大促 |
| S3 | 店出折扣使公开可订 < 新地板（或 < 当前 BAR 且价已最高） | **关该低价 Rate Plan**，不是报名 |
| S4 | 价已最高、低价仍开 | 只关不涨；不报名换曝光 |
| S5 | 谁出资 Unknown **且** 折扣看起来会店出、幅度 > 围栏 −5% | 条件化：先要出资页，默认不报 |
| S6 | 连住/多晚促销会把 Peak 夜按弱日价锁死 | 不报或砍 Peak 日期 |
| S7 | 销售只给「不报就没量」，无规则原文 | NV，不当开门条件 |

### 3.3 只报肩日

Peak 已证实、肩日 On/Behind 且不热：

```
Peak：不报；关打穿地板的促销 Rate Plan
肩日：IF 店出 ≤ −3–5% 或平台出资 THEN 可报肩日日期
     ELSE 不报，改用自有连住包装（los-optimization）
必须能按日筛选；不能筛选 = 整段不报
```

## 4. 何时该关低价 Rate Plan，而不是报名

比「报不报」更常见的正确动作是 **关**：

```
Sellout / 压缩 / 事件 Peak + 低价仍开
  → close-low-rate-compression：今天关 < 新地板 的公开产品
价已最高 + 仍 Fast
  → 只关不涨（Protect）
用户拿着「大促报名」问，其实日期是高峰
  → 关该计划在高峰的库存，BAR Open
已有预付 799 / 限时 699 打穿 899
  → 先关这些，再谈新活动（先库存后渠道）
```

报名是**新开一层更低库存**。压缩路径上这与 P03「先关低价」相反。

## 5. 与已有启发式

- 不跟价：竞对比你低 ≠ 你该报大促。先 Pace/Pickup。  
- 围栏 −3–5%、不一夜 −15%：店出大促深度按这两档审；DTA 4–21 禁止一夜 −15% 当新 BAR。  
- 价已最高只关不涨：最高价日不报名。  
- 团询 Counter：促销团/批发泄漏同样拒或净价+禁售。  
- 无 No-show 史不给超售精确间夜：促销取消率未知时不靠超售补。  
- MinLOS=2 只盖 Peak：Peak 上的「连住优惠」若店出深折，关；肩日可用浅连住围栏。
