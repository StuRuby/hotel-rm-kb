周六，180 间城市商务店（Simulation）。Remaining 14，Pace Ahead，公开灵活 BAR 799。Component/suite-pool：虚拟套房订出后物理 KNGS/PARLOR 被扣，套房池「看起来空」（Simulation 库存层，不是 Fact）。Accessible 子集卖完（属性旗，不是公开尺）。销售把库存喊成尺：组合套房占了所以 dump、无障碍卖完所以砍公开、套房池空了所以公开改 399、Component 扣了所以砸。本店 Component 字段 / 华住组合套房·无障碍 SOP / 默认 suite % = **NV，不编**。

### 2. Diagnosis

**T-Component**（过程仍 **P13 + P37**）。三把尺：公开 BAR 799 ≠ OPERA Component / Accessible·Features / Cloudbeds Split Inventory ≠ 分型 Remaining·Pace（→P13/P37）。库存层 = 虚拟扣减 + 属性旗，不是 BAR Type。形 A 混尺 + 形 B 改尺 399 + 形 C Accessible 当定价杠杆（禁）。Ahead 夜：库存层不被允许改公开 BAR。**≠ T-Floor ≠ T-Tax ≠ T-Staff ≠ capacity OOO 核。**

### 3. Opportunity / Risk

机会：拆尺后高峰仍 Hold 公开灵活，库存留在 Component/Accessible/Split Inventory 层，不必砍尺。风险：把套房池/无障碍训练成新 BAR；把「Component 扣了」读成「公开也跟 399」；把虚拟 OCC 读成必须 dump。

### 4. Recommended Action

