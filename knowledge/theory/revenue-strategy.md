## 0. 一句话

**预算差了 10%，不等于预测错了，更不等于下周全砍。**  
Revenue Strategy 管的是：**这一季站哪条价格带、预算是目标不是需求、谁有权动 BAR。** 今晚这一间仍走 Pace + BAR + 贡献。把目标缺口当成需求死亡，会在月中制造恐慌性降价。

```
Naive（禁止）     预算差 10% → 下周全砍；品牌底 699 但 Pace 差 → 偷偷砸穿；店长要 OCC 压过收益
Strategy（本卡）  Budget = 目标；Forecast = 无偏估计；品牌底价 = 约束不是建议
                  Pace 落后 → 先围栏/库存/渠道/限制
                  仍死 → 书面商业例外 + Watch，不静默 dump
今晚             仍 BAR + 贡献；GOP/TRevPAR 看季，不单独定今晚价
```

完成标准：用户说「预算差了 10% 要不要把下周全砍」「集团说品牌价不能低于 699，Pace 很差怎么办」「店长和区域收益意见打架听谁的」→ 能先拆对象，再给动作；**不编** 699 表、不编完成率门槛、不编集团 SOP。

三句（顾问出口）：

1. 预算差了不等于预测错了，更不等于下周全砍。  
2. 有品牌底价就先动围栏/库存/渠道，不偷偷砸穿。  
3. 店长要 OCC、收益要 GOP 时，用贡献和 Pace 说话，不拿预算当刀。

## 1. Budget 是目标；Forecast 是无偏估计

HSMAI Academy Glossary（**A，2026-08-22 打开**；词条级，不是本店 SOP）：

| | **Budget（预算）** | **Forecast（预测）** |
| --- | --- | --- |
| 是什么 | 管理层**想达到**的量化期望 / 计划 | 对**将会实际达到**的估计 |
| 更新 | 可能一年才改一次 | 按店型周 / 月 / 季更新 |
| 用途 | 对实际算差异；可触发绩效薪酬 | 短操：排班、战术定价、投放、分销 |
| 薪酬 | 预算 vs 实际**可以**动奖金 | 改预测**不**动绩效薪酬 |
| 一句话 | 生意**想去**哪 | 生意**正在去**哪 |

同页 Pace to Budget（A）：`(OTB / Budget) × 100`。这是**对照尺**，不是「低于某 % 就必须砍 BAR」。**禁止**把用户口述「差了 10%」写成库内门槛。

本库对象（与 `forecast-framework.md` §6 一致，不另起口径）：

```
OTB      = 事实位置
Forecast = 对尾巴的无偏估计（可每周改；带区间）
Budget   = 财务目标（改得慢，常偏乐观）
冲突时：信 OTB → 用 Forecast 决策 → Budget 只作对照，不单独当 Behind 铁证
```

**混用的典型伤害（B / Hypothesis）：** 月中发现 YTD 或下周 vs 预算 −10%，把 Forecast 上抬去「看起来能完成」，或反过来把 BAR 一夜砸穿去买 OCC。前者污染预测，后者污染价格带。HSMAI Forecast 词条把战术定价挂在 **Forecast** 上，不是挂在 Budget 缺口上。

HSMAI Revenue Optimization Advisory Board（*The Budget Process*，Morrobel；**B** 协会讨论，偏 2023 环境，**不是** 2026 法定 SOP）：业主要增长数字时预算会不现实；有人做两套——给业主的预算 vs 策略对齐的现实预测。另一篇 *Improving the Budgeting & Forecasting Process*（A 协会洞察）：用当前乐观预测钉死收入目标，会把预算做成不可达。顾问用法：**先改预期 / 先拆缺口来自量还是价**，不要用「完成率」当刀。

CoStar/STR（A/S，市场级）：Hotel Market Forecast ≠ 单店 Budget；Forward STAR 的 Occupancy on the Books = 确认在手，也不是 Budget。三套对象不要并成一张「差了 10%」。

**顾问动作（不是完成率表）：**

| 看见 | 先做什么 | 不要做什么 |
| --- | --- | --- |
| 预算差、Pace On、Pickup 匹配曲线 | **改 Forecast / 改预期**；Hold BAR | 为追预算砍下周 |
| 预算差、Pace Behind、市场也弱 | 不砸公开 BAR（`do-not-cut-price-market-also-weak.md`） | 「完成率不够所以跟到底」 |
| 预算差、只是 overlay / 事件假设错 | **P17**：先改判断 | 用错误 Forecast 追 Budget |
| 预算差、店长要 OCC | 贡献 + Pace 说话（§3–4） | 把 GOP 换成入住率去填洞 |

决策卡：`recommendations/dont-cut-to-hit-budget.md`。

## 2. 价格带 / 品牌底价 = 策略约束

品牌底价、BAR 带、公开最低可售，是 **strategy constraint**，不是「Pace 差就可以改的建议价」。

**本库不持有任何集团最低价表。** 用户没说地板 → **本卡品牌底不适用**，不要发明 699 / 华住表 / 「经济型不能低于 __」。用户说了「不能低于 699」（或任何数字）→ 把该数字当 **用户声明的约束** 执行，仍不升为本库 Fact。

公开互证（级写清）：

- HSMAI GDS 审计实践（A，协会战术文）：BAR 是每日默认公开价；**不应有更低价，除非 qualified / fenced**。支持「公开带完整；折扣走围栏」，不是某品牌的 699。
- Duetto Resource Hub *Optimize Floor and Ceiling Strategies*（**A Vendor**）：pricing strategy 的 floor/ceiling 是折扣带，**不是**最低价；最低价应设在 GameChanger → Strategy → **Min/Max Bounds**。系统会尊重 minimum。本库只借「最低价是显式约束」这一句，不抄厂商操作路径当集团 SOP。
- CRME 4e TOC（A，**只引章名**）：Ch.1 *From Revenue Management to Revenue Strategy*；Ch.2 *Fundamentals of Revenue Strategy*（含 *Adjusting a Revenue Strategy During Extreme Market Changes*）；Ch.4 *Brand Central Revenue Management*。认证把品牌中央收益单列，**不提供**本店底价。
- CRME Ch.9 小节名 *Strategic Pricing* / *Discounting* / *Rate Fences*：战略价与战术折扣分开。折扣默认走围栏，不先砸公开 BAR。

**Pace 落后时的顺序（Hypothesis，与 P02 幅度兼容）：**

```
1) 先查库存/渠道是否误关、限制是否过严（假慢）
2) 围栏 −3–5%（会员/预付/小配额），且围栏仍 ≥ 用户声明的品牌底
3) Mix：关穿底产品、按净排序（P20）；不高峰 dump 促销（P18）
4) 限制：淡日过严先松（P33）；高峰不靠砍 BAR 清库存
5) 仍死 → 升级为「商业例外」：书面、有截止日期、有 Watch，不静默砸穿
6) 禁止一夜 −15%；禁止把 BAR 对齐自杀竞对（P16）
```

P02 第一刀围栏 −3–5% **仍然可以**，条件是落点 **高于** 用户声明的品牌底。穿底的围栏 = 无效动作，改配额或改产品，不要「先破了再请示」。

仍死也不等于今晚必须破。破底是 **例外**，不是战术。例外至少写：Stay Date、原 BAR、声明底、拟议价、为什么围栏不够、谁批准、何时收回。Watch：24/48h 净 Pickup；破了没有量 → 立刻收回，不是再砍一刀。

决策卡：`recommendations/do-not-break-brand-floor.md`。

## 3. Cluster vs Property：谁拥有 BAR / 促销 / 团队

没有一份 2026 公开「全球集团权责 SOP」。组织是 **用户输入**。顾问先问组织图，再发言。

已有骨架（不另起口径）：`theory/rm-daily-routine.md` §1 Property / Cluster / Central；HSMAI VoRM 2021 把 On-property vs Cluster 当正式角色切分（A 调查，过时风险：不得写成 2026 工时定额）。

CRME 4e TOC Ch.4 *Departmental Integration* 小节名（A，只引名）：

- On-Property Revenue Optimization  
- Centralized Revenue Optimization  
- Outsourced (Third-Party) Revenue Optimization  
- Brand Central Revenue Management  

**Hypothesis（可问，不可当本店事实）：**

| 杠杆 | 常见归属 | 打架时顾问站哪 |
| --- | --- | --- |
| 公开 BAR / 价格带 | Cluster / Central / 品牌中央更常见 | 守带；单店「今晚为了 OCC 改带」要升级 |
| 会员 / 预付围栏、渠道配额 | 店或 Cluster 执行，带仍由上一级定 | 可动围栏，不动地板 |
| 团队 / 宴会占房 | 销售主谈，收益算置换（P10 / P30） | 用贡献和 displacement，不投票 |
| 促销报名 | 店或渠道经理常想报 | 整段 P18；高峰 / 穿底 / 出资未知 → 不报 |

「店长要 OCC、区域收益要 GOP」：不是谁官大听谁。用 **Pace 是否真落后、贡献是否为正、是否高峰、是否有用户声明的品牌底**。OCC 是结果不是目标；GOP 看季（T19），今晚这一间仍贡献 + BAR。预算完成率不是裁决。

Cluster 注意力是瓶颈（日常卡已写）：顾问每店 1 个主动作，禁止「全组合下周统一 −15%」这种假战略。

## 4. 何时不追 OCC

任一条成立 → **不要为了入住去砍公开 BAR / 砸品牌底 / dump 399**。不是「适当观察」。

| 关闭 | 为什么 | 先调用 |
| --- | --- | --- |
| **已证实 Peak / Pace Ahead / Fast Pickup** | 机会成本不是 0；买 OCC 是在卖高峰 | P01 / P09 / P03 |
| **用户声明了品牌底，拟议价穿底** | 策略约束；静默砸穿毁带 | 本卡 §2 · `do-not-break-brand-floor.md` |
| **贡献 ≤ 0**（或成本未知却要已知深折） | OCC↑ GOP↓ | T19 · `do-not-sell-below-contribution.md` |
| **排名 / 曝光 FOMO** | 库存/比价/内容未查就砍 = 用价买算法 | P35 · `dont-cut-for-rank.md` |
| **价格战、对方自杀 dump** | 跟到底邀请第二轮 | P16 · `ignore-comp-undercut.md` |
| **预算差、Forecast 其实 On** | 目标 ≠ 需求 | 本卡 §1 · `dont-cut-to-hit-budget.md` · P17 |

弱平日（P12）**可以**浅围栏，前提：贡献仍为正、**不低于用户声明底**、不是一夜 −15%、不是把 BAR 永久改成地板。

## 7. Diagnose 三问（用户原话）

1. **「预算差了 10% 要不要把下周全砍了？」**  
   10% 是用户数字，不是门槛。拆：Pace vs 曲线、市场是否冰、缺口是量还是价。Pace On → 改预期。真 Behind → 围栏，不是全周 BAR −15%。

2. **「集团说品牌价不能低于 699，Pace 很差怎么办？」**  
   699 是**用户声明约束**。先围栏/库存/渠道；仍死则书面例外 + Watch。不偷偷砸穿。用户没说地板 → 不要补 699。

3. **「店长和区域收益意见打架听谁的？」**  
   听组织图（先问）+ 贡献 + Pace。不听「预算当刀」。店长要 OCC、收益要 GOP 时，OCC 不是目标。

再要的 3 个数（有则写、无则 Unknown）：**(a) 用户声明的公开底价（没有就写无）(b) 同 DTA Pace / 3D Pickup (c) 拟议价的净价与变动成本（穿贡献则关）。**
