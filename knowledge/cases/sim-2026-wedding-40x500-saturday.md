## 1. Intake

口径：Pickup 为间夜。OO=0 Hypothesis。Expected Transient 用「OTB + 用户经验最终」拆日，标 Hypothesis。  
F&B **80,000 = Simulation 用户认领贡献**，不是餐标普查、不是 STR。  
套餐含场地 → 不另加厅租，Meeting_opp=0 并声明。  
佣金未给 → 团客房按 Gross 500，散客按 Gross BAR（可能高估散客机会成本）。

| 项 | 9/11 周五 | 9/12 周六 | 9/13 周日 |
| --- | --- | --- | --- |
| OTB 间夜 | 84 | 140 | 76 |
| Remaining | 116 | 60 | 124 |
| 3D 日均 | 2.0 | 8.0 | 1.7 |
| Pace vs LY | +2pp On | **+16pp Ahead** | +2pp On |
| BAR vs 最低竞对 | +20 | +30（已在 899–999 带内） | +30 |
| 用户经验最终散客 OCC | 60% → ET **120** | 94% → ET **188** | 55% → ET **110** |
| 团间 | 8 | 40 | 4 |

**Displacement 计算假设（必须保持标签）：**

```
H1 Capacity = 200，OO = 0
H2 ET 周五 120 / 周六 188 / 周日 110（用户经验点估计）
H3 被挤散客价 = 各日公开 BAR Gross（929 / 699 / 659）。净价未知
H4 团佣金 = 0（直订、未给费率）
H5 F&B_contrib = 80,000 记在周六宴会夜（Simulation 用户认领，不是 Fact）
H6 Meeting_opp = 0（无另售线索，声明）
H7 套餐含厅 → 不把厅租再加一次
H8 Wash：14 天可减无罚，无本店婚宴史，不填 %；当风险不进点公式
H9 LOS：周六大块可能挡周五到、周六走的连住散客。周五容量仍宽（120+8≪200），不装精确 LOS 间夜，点名为 Unknown
H10 不假设拒块后周六 BAR 会再涨（若涨，散客机会成本更高）
```

预选 3 个补数：周六更干净的 Transient Forecast；贡献 8 万是否已扣变动成本；客房块能否改截止。

## 2. Situation

200 间仿真店。分析日 8/22。婚宴 9/12 晚。占房周五 8、周六 40、周日 4，全 500 元。周六 DTA 21，OTB 70%=140，3D +24，vs LY +16pp，BAR 929，竞对 899–999。用户经验无婚宴周六散客最终 94%。用户认领宴会贡献 80,000（Simulation）。用户问题：接不接 40×500；要不要把散客关了。

## 3. Diagnosis

| # | 判定 |
| --- | --- |
| 拆单 | 宴会一笔；客房三夜三笔。禁止「餐很高所以整周末接」 |
| 周五置换 | 120+8−200 = **−72 → Displaced=0** |
| 周六置换 | 188+40−200 = **28 间** |
| 周日置换 | 110+4−200 = **−86 → Displaced=0** |
| 周六客房-only | 团 40×500=20,000；挤 28×929=26,012 → **−6,012** |
| 整段客房 | 团 26,000；挤 26,012 → **约 0**（把亏的周六藏进肩日的 +6,000） |
| TRM 若硬接 | −6,012 + 80,000（Simulation 贡献）−0 厅机会成本 → 整段看似大正 |
| Pace | **周六 Ahead+Fast**（Days-to-Sellout 60/8≈7.5 < DTA 21）。周五/周日 On、剩余厚 |
| 价 | 周六 BAR 已在 899–999 带内、高于最低竞对，不是「散客卖不动才 dump」 |
| 关散客 | 若关零售，尾部 60 间不再走 929 层 → dump 升级。**拒绝** |
| 功能空间 | 无第二场线索；套餐含厅 → 不双计 |
| 贡献数字 | 有（Simulation 认领）。**不是**口号。但仍过不了「高峰能卖满」闸 |

```
Fact: 团 8/40/4 ×500；周六 OTB 140、3D +24、Pace +16pp；BAR 929；竞对 899/949/999
High-probability: 周六会挤散客；周五/周日客房不挤
Hypothesis: ET 120/188/110；佣金 0；929 为被挤层
Simulation（非 Fact）: F&B 贡献 80,000
Unknown: 净价、变动成本、Wash %、OO、LOS 精确间夜
```

**主诊断：** 周六是已证实 Peak（Ahead+Fast+用户 94% 最终）。40×500 客房-only 为负。整段客房≈0 是假象。贡献 8 万（Simulation）盖得过置换，但 T18：**高峰能卖满散客 → 仍 Counter 客房、留宴会**。  
**不要关散客。**  
**问题树：** O12 · §34；周六兼 §7 Pace Ahead。  
**Naive 整单 Accept / Naive 整单拒宴会：都不对。**

## 5. Recommended Action · **Counter**

**不 Accept 原 40×500×周六。不拒宴会。不关散客。不整周末同一把刀。**

**Counter A（房量，首选若对方预算死 500）**

```text
宴会 9/12：Accept 留下（贡献 80,000 为 Simulation 用户认领）
9/11 周五：Accept 8 间 × 500     # Displaced=0
9/13 周日：Accept 4 间 × 500     # Displaced=0
9/12 周六：最多 12 间 × 500
  12+188−200 = 0 间置换
  其中 must-keep：婚房 1 + 家长房 4 = 5 间（计入 12，不另加）
  宾客最多 7 间 × 500
  其余亲友走公开 BAR（929 带），不要关散客
取消：客房块改为 DTA 14 截止且减房有代价，或 30% 不可退（Hypothesis 护栏）
Do-not-do: 周六仍给 40 间 × 500；把散客关了
```

**Counter B（价，若对方要锁 40 间周六）**

```text
周五：8×500（不挤）
周日：4×500（不挤）
周六：40 间
  保本 ≈ 28×929/40 = 650
  BAR 70–85% = 650–790；泄漏警戒：相对 929 差 >15% → 下沿收到 790
  区间：790–860，首选 799
  799×40=31,960 vs 机会成本 26,012 → 周六客房由负转薄正（数量级，禁止写成精确增收）
婚房+家长房 5 间可维持 500（结构优惠）；其余 35 间走 790–860 首选 799
  → 等价混合：5×500 + 35×799
散客：保持可订。不要关
```

**Counter C（结构，高峰房按 BAR + 只办宴会）**

```text
宴会留下
周六客房不锁 40 间团价；must-keep 最多 5 间协议（500 或按合同婚房）
其余亲友按 BAR 899–999 带散订
周五 8 / 周日 4 仍可 500
```

**Reject 条件：** 对方坚持 **40×500×周六 + 把散客关了**（无论餐标口号或 8 万 Simulation 贡献）→ **Reject 周六客房大块**，宴会可留，must-keep 5 间可另议。写「若接受 A 或 B 或 C 则收回拒」。

**Displacing 哪些散客日期：**

- 原条件：主要 **9/12 周六约 28 间** 零售 929。  
- 9/11、9/13 客房本身不挤。  
- 关散客会把周六剩余 60 间的零售层一并让掉，置换更大。

**散客 BAR：** 本仿真主主动词是房块 Counter，不是改 BAR。周六已 Ahead+Fast、价在带内未到最高竞对 999 → 若另问涨多少，走 P01 档 A，**不在本卷把涨 BAR 写成婚宴结论**。价已最高才只关不涨；本卷 929 < 999，不是价已最高。禁止为婚宴砸 BAR、禁止一夜 −15%。

**MinLOS：** 周六可以是已证实 Peak → 可评 MinLOS=2 **只盖周六**（护肩日连住）。**不要**自动给周五/周日加 MinLOS。婚宴宾客要单晚周六，用 Counter 房价/房量解决，不要用 MinLOS 惩罚肩日。

## 6. Why

```
Naive: 餐很高 / 贡献 8 万 > 置换 2.6 万 → Accept 40×500，关散客锁房
  错在：高峰能卖满时 T18 仍要求 Counter 客房；关散客 = 把 929 层主动让出
Naive: 500<929 → 拒整单含宴会
  错在：周五/周日不挤；宴会贡献是另一笔（Simulation 用户已认领）
Naive: 整段客房 ≈0 → 接
  错在：周六单独 −6,012；整段平均把高峰亏藏进肩日

正确链：
  拆宴会 vs 占房
  周六 Ahead+Fast + ET 188 + 团 40 → Displaced 28 → 客房-only 负
  贡献 80,000（Simulation）盖过置换，但高峰能卖满 → Counter 客房、留宴会
  周五/周日 Displaced=0 → 可接 500
  散客保持开
```

理论：置换卡 §3.1 / §5.3；T18 §2–3；P30 十步。HSMAI 词条级 displacement（A 定义，无公式页）。未摘教材正文。未用厂商婚宴 Wash 18–28%。

## 7. Expected Impact

- 接受 A：周六客房不挤；宴会 8 万（Simulation）留下；肩日确定 12 间×500；零售尾部仍走 929 带。  
- 接受 B：周六 40 间靠近 799，客房由负转薄正；仍挤 28 间散客，用价补。  
- 接受 C：高峰库存几乎全给 BAR；宴会留下。  
- 硬接原条件：周六少收约 6,000 客房量级，另承担 14 天无罚 Wash。  
- 关散客：比硬接更差（零售层被关）。  
- 硬拒含宴会：丢掉用户认领的 8 万贡献（Simulation）且周五 8 间可能卖不完。

不编 GOP。不把 80,000 写成真实酒店利润。

